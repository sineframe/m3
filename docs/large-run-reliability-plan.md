# Fix plan for m3’s seven large-run limitations

This is the execution contract approved in the conversation. Implementation must retain every contract below. No monkey patches, speculative storage replacement, name-based policy whitelist, timeout-clock reset, secret-bearing snapshot, shared writable cache, uncancellable preparation thread, or weakened validation. All independent packages run in separate worktrees. Coordinator reviews the complete diff and checks evidence before integration; no agent self-accepts changes. Report design conflicts before deviating.

| Issue | Category | Triage | Solution |
|---|---|---|---|
| 1 | Startup deadlines and overloaded hosts | Confirmed P1 | Configurable phase/MCP deadlines, owned cancellation; optional admission later |
| 2 | Lost native errors | Confirmed P1 | Preserve redacted native causes across result/event surfaces |
| 3 | Missing native settings | Confirmed P1 core | Typed explicit native timeout/permission/network/filesystem settings; capability validation |
| 4 | Completed answers discarded | Confirmed P1 | Provenance-aware policy and retain response/evidence on violations |
| 5 | Claude argument expansion | Confirmed P2 | Full literal argv/env via protected native handoff |
| 6 | Session cache cost | Partially confirmed P3 | Opt-in immutable allowlisted seeds with private clone/copy |
| 7 | SQLite contention | Not reproduced | Real multi-CLI workload first; configurable existing busy timeout; no speculative backend |

## T: Secret transport contract (precedes snapshots and resolver)
Frozen configuration/profile/server env/header literals stay frozen for the invocation even if files are deleted or environment changes. Internal opaque LiteralHandle(run id, generation, slot) references point to a volatile immutable RunLiteralStore. No literal values or value fingerprints in ordinary serialized snapshots, provenance, workerinput or results. Named credential references resolve fresh locally at native launch and are pinned for that session; templates preserve exact literal segments and named references.
When controller literals exist, use an owner-only local Unix-domain socket (Windows current-user ACL named pipe), never TCP. A unique single-use per-worker capability and authorized slot manifest live in a protected ephemeral bootstrap capsule. Ordinary xdist workerinput carries endpoint/capsule paths and identities only. Worker opens without following symlinks, checks protection/ownership, unlinks capsule, authenticates over private IPC. Versioned bounded byte frames, no pickle; validate run/generation/full manifest atomically; reject partial transfer/replay/wrong run with value-free error. One finite total bootstrap deadline (default 30s, configurable in [tool.m3.worker_bootstrap].timeout_seconds), never per-frame reset. No registry means no broker/capsule cost. Fresh replacement workers receive original frozen values through fresh capability.
Controller retains registry until run ends and bootstraps finish. Worker retains complete local copy shared by kits for run lifetime; kit close does not erase it. Bootstrapped later sessions need no controller RPC. Deletion before/after bootstrap and replacement must work; controller loss before transfer fails, never rereads files. Remote workers cannot use local handles; require portable references or reject. Worker-origin explicit Python/profile literals use local registry and are not implicitly broadcast. Revoke/close/remove/drop references after owned cleanup settles; do not claim Python memory zeroization.

## A/S: User configuration, credentials, capabilities
Exactly ONE new flag: --m3-config PATH, across m3 test, m3 ci test, m3 doctor and direct pytest. Existing pyproject.toml [tool.m3] is the default; user adds settings manually. No invented benchmark.toml, auto-generation, generic --set, tuning-flag explosion or new environment variables. Existing m3.toml remains identity configuration.
Public m3.types usage: StdioServer(..., timeouts=McpTimeouts(startup_seconds=75)); agent.session(..., harness_timeouts=HarnessTimeouts(initialize_seconds=15)); typed CodexPermissions/other harness permission settings through selection.permissions/session.harness_permissions; CachePolicy and StartupAdmission on kit/run/session as applicable. Document runnable examples for every public type.
Example file settings: [tool.m3.harnesses.codex.timeouts] startup_seconds=90,total_seconds=120; [tool.m3.mcp_timeouts] startup_seconds=60; [tool.m3.servers.slow.timeouts] startup_seconds=75; [tool.m3.cli] project_python_timeout_seconds=60; [tool.m3.results] busy_timeout_seconds=30.
Merge only explicitly set leaves: defaults < file wide < file harness/alias < existing env < existing CLI < kit explicit < selection/harness/server/profile explicit < session/binding explicit. Omitted model fields inherit and native-backed UNSET stays unset through resolution/serialization. None disables optional total/load budgets only; required phase None invalid. TOML false only documented optional disabling; numeric bool invalid. Session initialize-only override retains startup=90,total=120. Aliases affect bound servers only, never introduce servers.
Schema validation before project Python probe. Native capability discovery cached by runtime version/digest/dialect/platform after resolution. Validate every effective final session request after every merge (including Python/profile overrides) before preparation or spawn; cache support facts, not approvals. Unsupported settings fail clearly, no fallback to broader permissions.
Controller snapshot authoritative; workers and kits do not reread files or configuration environment; explicit Python leaves overlay afterward. Snapshot uses T transport descriptors separately. Worker attempts to choose a different config fail. Standalone kits can discover settings normally. Doctor/provenance are redacted projections with nonsecret canonical digest, not raw-file or secret hashes.
Resolve credential references locally after capability validation and admission, immediately before native launch. Frozen literals come from local registry; refs use worker-local explicit inputs/env/provider; pin immutable launch bundle; register secrets for redaction before handoff/spawn, including rendered templates. Deferred MCP launches/native restarts reuse bundle. Rotation affects future launches, not existing sessions. Changing controller env does not update existing worker env. Unsupported live providers fail. Private native handoffs mode 0600; portable exports require portable refs or safe error.

## P/E/I: Startup and cancellation ownership
Lazy session entry may prepare workspace but does not launch native processes/acquire admission. Acquire host FIFO lease just before executable native startup at first send; no idle lease. While holding a lease native clocks continue; startup needing indefinite caller input must fail/clean up, not pause indefinitely. Defaults admission disabled; opt-in defaults 4 slots, queue timeout 300s; optional normalized load unsupported-platform error. Kernel-backed leases track native child ownership, not only controller death; no SQLite scheduler.
Preserve existing phase defaults; optional total unset. Total starts first owned preparation, counts active preparation and startup; excludes queue/caller idle only at explicit safe checkpoints; resume remaining budget. Runtime resolution/admission have separate bounded clocks. MCP initialization is inside native phase and total; earliest parent/child/first-send deadline wins. Native clocks end when ready; first-send includes deferred startup. Example prep consumes15/120,105 remains after queue; native90 contains MCP75, so late MCP remains bounded by parent. No request/frame retry resets deadline.
Preparation uses worker-owned reusable helper supervisor, owned process groups, unique staging per job. No uncancellable thread continuing to mutate published files. Workspace/cache materialization performs private writes, publishes atomically only for accepted generation before deadline and after handles closed/children joined. Capture has owned cancellable tasks/processes. Fence on timeout, cooperative stop then TERM/KILL; wait before delete. If operation cannot promptly stop, quarantine owned root, retain ownership and prohibit publish/reuse/delete until writer death. EOF/controller loss kills owned groups. Uninterruptible IO cannot be instantly stopped: guarantee controller bounded return and isolate further writes. Arbitrary uncancellable custom hooks unsupported with total budget.
Existing cleanup attempt10s/cancel3s bounds, clip nested remaining budgets with no reset. Terminate processes before collecting artifacts; preserve original failure plus cleanup failure. Surviving native startup retains fenced admission ownership until confirmed death. Test stalled copy, ignored TERM, inherited pipes, controller EOF, late publication, quarantine and idle lazy sessions.

## B/C/D/F/H/G solutions
B: Preserve native error text/code/phase/evidence through all result/event surfaces, bounded projection/truncation, redact with launch-bundle registry; fail closed if secrets cannot safely be projected. Existing errors remain compatible.
C: Distinguish actual MCP, harness built-in, unknown provenance at decode; NEVER allow via server name alone. Bound-server identity wins collisions. Allow known native introspection, enforce actual MCP binding/policy; retain completed response+trace+violation on failed result and through persistence.
D: Full resolved literal command/args/environment into protected handoff so Claude cannot pre-expand user argv. Spawn argument arrays, no added shell quoting workaround; preserve all string semantics and deferred credential bundle.
F: Emit native settings only when explicitly requested, correct native units; reject incompatible global/per-server settings. Codex profile vs legacy sandbox mutually exclusive; profile written natively and omit legacy overrides; verify activePermissionProfile. Support named/defined profile, native filesystem policy, network; no universal OS sandbox, never grant broader fallback. Separate filesystem permissions from interaction approval policy.
H: Isolated default; retain existing managed packages and pinned OpenCode catalog reuse. Seed key pins harness version/platform/relevant config. Explicit immutable-cache allowlist excludes secrets/project/conversations/logs/databases. Atomic seed publication, private clone or copy, NEVER hardlinks/shared writable cache. Quarantine corruption; provenance and cold/warm cost measurements.
G1: Six actual m3 CLI processes with four workers each, deterministic server/agent fixture, shared-store full run manifests/events/readers/refresh and termination; compare separate DBs. Existing WAL,5000ms busy timeout and guarded rollback already exist. G2 configurable busy timeout after A. No speculative storage backend or blanket retry; if original failure remains unreproduced report honestly and keep scope narrow.

## Performance gates
Controlled real adapter protocol fixtures + capture + stdlib MCP + SQLite; no providers/model latency/download/network. Scenarios fresh process/session, warm repeated sessions, six processes/four workers/shared DB. Twenty paired blocks,50 trials/revision/block (1000/revision); ABBA randomized seeded order on controlled host. Simultaneous95% paired-block bootstrap CI for median and p95 ratios: upper <=1.03/1.05 passes, lower above threshold fails, overlap adds20 blocks up to80 then inconclusive blocks release. Dedicated performance job; cold bootstrap/helper memory/lifetime/transfer-once counts included. Native end-to-end compatibility/performance separately, no provider-latency percent gate. Opt-in admission/cache costs measured and reported. Never weaken ownership to meet gate.
